# rfc9162

`rfc9162` hashes a tree of 32-byte leaves. Record bytes go through [`leaf_hash`](../reference/rfc9162.md). The root and the proofs are functions of the leaf slice. Storage and the signed-note envelope are the other two crates.

## Check a proof against other inputs

`verify_inclusion` returns true for the leaf at the index the proof was built for. The same path with another leaf, another index, a shorter path or another root returns false. `verify_consistency` returns true for a prefix and false when the sizes are swapped. `from_hex` accepts the 64 lowercase digits `hex` writes. Uppercase digits return `None`.

## Empty log

The root of an empty leaf slice is SHA-256 of the empty input, `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`. `inclusion_proof` on an empty slice returns `None`. A one-leaf tree's root is that leaf. The leaf hash of an empty entry, which is the RFC 6962 one-leaf root for the empty input, is `6e340b9cffb37a989ca544e6bb780a2c78901d3fb33738768511a30617afa01d`.

The eight published roots from the RFC 6962 vector set are checked in `crates/rfc9162/tests/rfc6962_vectors.rs`.

The [Merkle tree](../topics/merkle-tree.md) page is the shape behind these hashes. To store the entries, use [rfc9162-tiles](rfc9162-tiles.md).
